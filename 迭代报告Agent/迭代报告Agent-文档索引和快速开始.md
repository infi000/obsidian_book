## 📌 关键概念速览

### VCS 适配器（Adapter Pattern）

```
问题：GitLab 和 Bitbucket 的 API 不同
解决方案：创建抽象的 VCSAdapter，每个 VCS 实现一遍

VCSAdapter（抽象）
├─ getMergedPRs()
├─ getFileStat()
└─ ...

GitLabAdapter（实现）
├─ 调用 /api/v4 endpoints
└─ ...

BitbucketAdapter（实现）
├─ 调用 /2.0 endpoints
└─ ...

好处：
• 代码复用高
• 易于扩展新的 VCS（GitHub、Gitea 等）
• 业务逻辑与 VCS 细节分离
```

### Agent 工作流

```
1. 输入：上线分支名（release/main）
        ↓
2. 获取：所有合并的 PR/MR
        ↓
3. 统计：每个 PR 的文件改动
        ↓
4. 聚合：总统计（文件数、代码行数等）
        ↓
5. 生成：Markdown 格式的报告
        ↓
6. 输出：保存为本地文件

耗时：通常 30-60 秒
```

### 环境变量配置

```
必需：
├─ VCS_TYPE（gitlab 或 bitbucket）
├─ VCS_BASE_URL（VCS 服务器地址）
├─ Token（GitLab 的 GITLAB_TOKEN 或 Bitbucket 的 BITBUCKET_TOKEN）
└─ 其他 VCS 特定参数（Project ID / Workspace / Repo Slug）

可选：
├─ RELEASE_BRANCH（默认 release/main）
└─ BASE_BRANCH（默认 main）

位置：项目根目录的 .env 文件
```

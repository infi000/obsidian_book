# 项目概览 - SFCODE.md 编写指南

`SFCODE.md` 是项目的全量规范文档，所有 AI 工具都从这个文档读取项目信息。

## 核心 8 个部分

### 1. 项目概览

**用途**：让 AI 快速理解项目的核心业务和价值

**包含内容**：
- 项目名称和标语
- 项目描述（2-3 句）
- 核心业务领域
- 主要功能特性（列表）
- 目标用户
- 项目状态（开发中/已发布）

**示例**：
```markdown
## 项目概览

**项目名称**：apodidae（鸟类物种管理系统）

**项目描述**：一个面向博物馆和研究机构的鸟类物种信息管理系统，提供物种档案、标本管理、数据分析等功能。

**核心业务**：
- 物种数据管理
- 标本信息存储
- 研究数据分析
- 学术发布

**主要特性**：
- 多维度物种分类
- 标本级细粒度管理
- 实时数据统计分析
- 国际化多语言支持
```

### 2. 项目目录结构与说明

**用途**：帮助 AI 理解代码组织方式

**包含内容**：
- 顶级目录说明
- 主要子目录的用途
- 重要文件的位置

**示例**：
```markdown
## 项目目录结构

```
src/
├── pages/              # 页面组件（路由层）
├── components/        # 可复用组件
├── services/          # API 服务和数据层
├── stores/            # 状态管理（Redux/Context）
├── hooks/             # 自定义 Hook
├── utils/             # 工具函数
├── styles/            # 全局样式
├── types/             # TypeScript 类型定义
└── constants/         # 常量定义

config/                # 配置文件目录
tests/                 # 测试文件
docs/                  # 项目文档
```

**重要文件**：
- `package.json` - 项目依赖和脚本
- `.env.example` - 环境变量模板
- `tsconfig.json` - TypeScript 配置
```

### 3. 主要技术栈介绍

**用途**：让 AI 了解项目使用的技术

**包含内容**：
- 前端框架和库
- 后端技术（如适用）
- 数据库
- DevOps 工具
- 其他关键技术

**示例**：
```markdown
## 技术栈

### 前端
- **框架**：React 18+
- **语言**：TypeScript
- **状态管理**：Redux Toolkit
- **UI 框架**：Ant Design
- **HTTP 客户端**：Axios
- **构建工具**：Vite
- **测试**：Jest + React Testing Library

### 后端（API）
- **框架**：Node.js + Express
- **数据库**：PostgreSQL
- **认证**：JWT

### DevOps
- **版本控制**：Git
- **CI/CD**：GitHub Actions
- **部署**：Docker + Kubernetes
- **监控**：Prometheus + Grafana
```

### 4. 开发与运行环境介绍

**用途**：帮助 AI 配置和运行项目

**包含内容**：
- 必需的系统软件版本
- 安装依赖的命令
- 启动开发服务器的命令
- 构建和部署命令
- 环境变量配置

**示例**：
```markdown
## 开发与运行环境

### 系统要求
- Node.js >= 16.0.0
- npm >= 7.0.0
- Git

### 安装与启动

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入必需的配置

# 3. 启动开发服务器
npm run dev

# 4. 打开浏览器
http://localhost:5173
```

### 常用脚本
```bash
npm run dev        # 启动开发服务器
npm run build      # 构建生产版本
npm run test       # 运行测试
npm run lint       # 代码检查
npm run format     # 代码格式化
```

### 环境变量
- `VITE_API_BASE` - API 地址
- `VITE_APP_ENV` - 运行环境（dev/test/prod）
```

### 5. 核心开发要求

**用途**：规范 AI 生成的代码

**包含内容**：
- 代码规范（命名、风格）
- 文件组织规范
- 性能要求
- 安全要求
- Git 工作流

**示例**：
```markdown
## 核心开发要求

### 代码规范
- 使用 TypeScript，禁止 any 类型
- 采用 ESLint + Prettier 进行代码检查
- 组件使用函数式写法，优先使用 Hook
- 文件名使用 camelCase，组件使用 PascalCase

### 文件组织规范
- 一个文件对应一个组件或功能
- 相关文件放在同一目录
- 避免循环依赖
- 导入优先级：React > 库 > 本地模块

### 性能要求
- 首屏加载时间 < 3 秒
- 列表页面支持虚拟滚动（数据 > 100 条）
- 组件应使用 React.memo 或 useMemo 避免不必要渲染

### 安全要求
- 敏感信息（密钥、token）只存储在后端或 localStorage
- 禁止在代码中硬编码密码和密钥
- 进行 XSS 防护（使用 DOMPurify）
- 用户输入必须验证
```

### 6. AI Agent 技能介绍

**用途**：告诉 AI 可以使用哪些技能

**包含内容**：
- 可用的技能列表
- 每个技能的简要说明
- 技能的触发场景
- 技能文档位置

**示例**：
```markdown
## AI Agent 技能

### 可用技能列表

| 技能名 | 说明 | 触发场景 |
|------|------|---------|
| code-review | 代码质量审查，包含 12 项检查维度 | PR 审查、代码检查 |
| code-generation | 自动代码生成，支持页面和组件 | 新建功能、快速原型 |
| testing | 自动化测试脚本生成和执行 | 编写单元测试、E2E 测试 |
| documentation | 文档和注释自动生成 | 完善文档、补充注释 |
| api-design | API 接口设计和文档生成 | 设计新 API、生成 Swagger 文档 |

### 技能使用指南
- 所有技能文档位置：`.sfcode/skills/`
- 技能注册表：`.sfcode/agents/AGENTS.md`
- 技能工作流：`.sfcode/workflows/`
```

### 7. 备注 - 对 AI 的系统性约束

**用途**：告诉 AI 不能做什么

**包含内容**：
- 禁止操作（删除代码、修改敏感文件）
- 特殊规则（某些文件不能修改）
- 注意事项（性能瓶颈、已知问题）
- 系统约束（内存限制、超时限制）

**示例**：
```markdown
## 对 AI 的系统性约束

### 禁止操作 ⛔
- 不要修改 `.env` 或 `secrets.json` 文件
- 不要删除已发布的 API 接口
- 不要修改数据库 schema（需要审批）
- 不要更改核心路由配置

### 特殊规则 ⚠️
- 新建页面必须在 `src/pages/` 目录
- 新建组件必须在 `src/components/` 目录
- 所有 API 调用必须经过 `services/` 层
- 不要直接修改全局状态（Redux），使用 action

### 已知问题 🐛
- 列表页在处理 > 1000 条数据时会有性能问题（需要分页）
- Safari 浏览器不支持某些 ES2020+ 特性（需要 polyfill）
- 在中国网络环境下，外部 CDN 可能无法访问

### 系统约束
- 单个函数不超过 50 行代码
- 单个文件不超过 300 行代码
- 不要导入超过 10 个依赖包
```

### 8. AI 相关目录对应的功能

**用途**：说明 `.sfcode/` 目录的用途

**包含内容**：
- 各子目录的功能说明
- 如何使用各个目录
- 何时添加新内容

**示例**：
```markdown
## AI 相关目录功能说明

### `.sfcode/skills/`
项目级 AI 技能存储目录。每个技能是一个独立的目录，包含：
- `SKILL.md` - 技能定义和使用说明
- `references/` - 参考文档和最佳实践
- `scripts/` - 技能执行脚本
- `templates/` - 代码模板

**何时添加**：当需要创建项目特定的技能（如特定的代码生成工具）

### `.sfcode/agents/`
Agent 定义和路由文件。包含：
- `AGENTS.md` - 技能注册表和路由
- `*.yaml` - 具体 Agent 定义

**何时修改**：当添加新技能或更改现有技能时，需要更新 `AGENTS.md`

### `.sfcode/workflows/`
工作流定义文件。包含：
- `main.yaml` - 主要工作流
- 其他工作流 YAML 文件

**何时修改**：当项目工作流发生变化时（如新增开发流程）

### `.sfcode/reports/`
项目输出报告存储目录，按版本和类型分类。包含：
- `v*/CodeReview/` - 代码审查报告
- `v*/Test/` - 测试报告
- `v*/Design/` - 设计文档
- `v*/Dev/` - 开发总结

**何时使用**：自动生成的报告会存储在此目录
```

## 最佳实践

1. **清晰简洁** - 避免过长的段落，使用列表和表格
2. **代码示例** - 用实际代码示例说明规范
3. **定期更新** - 项目信息变化时及时更新
4. **版本控制** - 提交到 Git 中，保持历史记录
5. **链接引用** - 可以链接到详细文档（如果存在）

# 开发规范总览

欢迎来到项目规范中心。这里汇集了项目的所有开发规范。

| **命名规范** | 如何给文件、变量、函数命名 | [[naming-conventions\|命名规范]] |

## 📖 为什么要遵守规范？

- ✅ **团队协作** - 所有人遵守同样的标准，代码容易理解
- ✅ **代码质量** - 规范帮助避免常见错误和陷阱
- ✅ **易于维护** - 新成员能快速熟悉代码风格
- ✅ **减少 Review** - 减少关于风格的讨论，重点讨论逻辑

## 📋 规范检查清单

### Code Review 时检查什么？

使用 [[code-standards|代码规范]] 检查：
- [ ] 变量、函数、类的命名是否符合规范
- [ ] 代码注释是否清晰
- [ ] 代码缩进和格式是否正确
- [ ] 没有使用禁用的语法或做法

### 提交代码前检查什么？

使用 [[git-workflow|Git 规范]] 检查：
- [ ] 分支名称是否符合规范
- [ ] 提交信息是否清晰
- [ ] 没有提交不应该提交的文件（node_modules、build等）

### 新建文件时检查什么？

使用 [[file-structure|文件结构]] 和 [[naming-conventions|命名规范]] 检查：
- [ ] 文件放在正确的目录
- [ ] 文件名是否符合规范
- [ ] 文件内容的组织方式是否符合规范

## ⚡ 5 分钟快速了解

### 核心概念：什么是 Skill 2.0？

从**单文件混乱** → **模块化清晰**

```
❌ 老办法（Skill 1.0）：
   一个 500+ 行的 SKILL.md
   ├─ 所有规则混在一起
   ├─ 上下文超载
   └─ 维护困难

✅ 新办法（Skill 2.0）：
   轻量的 SKILL.md（索引）
   ├─ rules/ （规范）
   ├─ workflow/ （流程）
   ├─ templates/ （模板）
   └─ 模块化、易维护、可扩展
```

### 两种 Skill 架构

| 类型 | 用途 | 结构 | 何时用 |
|-----|------|------|--------|
| **知识库型** | 规范查询 | 索引 + N 个独立文件 | "代码怎么写？" |
| **工作流型** | 流程执行 | 索引 + 5 个顺序步骤 | "怎么审查代码？" |

## 🎯 常见问题速答

### Q: 我应该怎么部署这两个 Skill？

A: 三步走
```bash
1. 找到 Claude Code Skill 目录
   ~/.claude/skills/

2. 复制文件夹
   cp -r "Skill 示例 1 - 知识库型" ~/.claude/skills/frontend-team-standards
   cp -r "Skill 示例 2 - 工作流型" ~/.claude/skills/code-review-assistant

3. 在 Claude Code 中使用
   /frontend-team-standards  或  /code-review-assistant
```

### Q: 知识库型和工作流型有什么区别？

A: 见下表：

| 维度 | 知识库型 | 工作流型 |
|-----|---------|---------|
| 用途 | 查规范 | 做审查 |
| 例子 | "怎么命名?" | "怎么审查?" |
| 流程 | 随意查询 | 逐步执行 |
| 文件数 | 6 个 | 14 个 |
| 复杂度 | 简单 | 复杂 |

# 第一步：理解需求和上下文

## 你的任务

在开始详细的代码审查前，你需要彻底理解这个 PR 的背景：

### 1. 阅读 PR 信息

收集以下信息：
- **PR 标题和描述**：了解意图
- **Related Issues**：知道解决的是什么问题
- **修改文件列表**：快速浏览涉及的范围
- **Commit 历史**：理解实现步骤

提示问题：
- ❓ 这个 PR 做了什么？
- ❓ 为什么要做这些改变？
- ❓ 涉及哪些核心文件？
- ❓ 有没有破坏性改动？

### 2. 理解技术背景

```markdown
检查清单：
- [ ] 我理解了 PR 的业务需求
- [ ] 我了解了修改涉及的文件
- [ ] 我知道了这个功能的架构
- [ ] 我识别了潜在的风险点
```

### 3. 确定审查焦点

根据 PR 的类型，确定审查重点：

```
✅ 新功能开发
  → 重点：需求完整性、代码规范、可测试性

✅ Bug 修复
  → 重点：修复是否根本、是否引入回归

✅ 性能优化
  → 重点：优化效果测试、是否有副作用

✅ 重构
  → 重点：功能一致性、改进程度

✅ 依赖更新
  → 重点：版本兼容性、breaking changes
```

### 4. 准备审查环境（可选）

如果需要实际验证：

```bash
# 检出分支
git checkout feat/new-feature

# 安装依赖
npm install

# 运行测试
npm test

# 启动应用测试
npm dev
```

---

## 完成标志

当你能够清楚地回答以下问题时，进入下一步：

- ✅ 这个 PR 要实现什么功能？
- ✅ 为什么需要这个改动？
- ✅ 涉及哪些主要的文件和模块？
- ✅ 有没有潜在的架构风险？
- ✅ 我应该重点关注哪些方面？

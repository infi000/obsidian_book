# 代码质量检查清单

这是代码审查中最常检查的项目清单。

## 🔴 Blocking 问题

### 功能性

- [ ] 代码是否实现了所要求的功能？
- [ ] 功能是否有 bug？
- [ ] 是否处理了所有边界情况？
- [ ] 测试是否通过？
- [ ] 是否有破坏性变更（breaking changes）？

### 安全性

- [ ] 是否有 SQL 注入漏洞？
- [ ] 是否有 XSS 漏洞？
- [ ] 是否有敏感信息硬编码？
- [ ] 是否有身份验证检查？
- [ ] 是否有授权检查？

### 架构

- [ ] 是否违反了架构规范？
- [ ] 是否破坏了已有的 API？
- [ ] 是否与设计模式不符？

---

## 🟡 Should Fix 问题

### 代码规范

- [ ] 文件名是否符合规范？(PascalCase for components, camelCase for others)
- [ ] 变量名是否清晰？
- [ ] 函数名是否描述功能？
- [ ] 是否遵循 TypeScript 规范？(避免 any)
- [ ] 是否遵循代码风格？(缩进、空行等)
- [ ] ESLint 是否通过？
- [ ] Prettier 是否通过？

### TypeScript

- [ ] 是否定义了所有的类型？
- [ ] 是否使用了泛型？(而非 any)
- [ ] 是否有类型检查错误？
- [ ] Interface/Type 是否适当？

### React 规范

- [ ] 是否使用了函数式组件？(禁止 class)
- [ ] Props 是否有类型定义？
- [ ] Hooks 是否正确使用？
- [ ] useEffect 依赖列表是否完整？
- [ ] 是否有不必要的重新渲染？

### 可读性

- [ ] 代码逻辑是否容易理解？
- [ ] 是否需要更多注释？
- [ ] 函数是否太长？(超过 50 行)
- [ ] 文件是否太大？(超过 300 行)
- [ ] 是否有重复代码？

### 测试

- [ ] 是否添加了单元测试？
- [ ] 测试覆盖率是否足够？
- [ ] 测试是否有意义？(不是虚假测试)
- [ ] 是否需要集成测试？

### 性能

- [ ] 是否有明显的性能问题？
- [ ] 是否有 N+1 查询问题？
- [ ] 大列表是否使用了虚拟化？
- [ ] 是否有不必要的计算？

---

## 🟢 Nice to Have 问题

### 最佳实践

- [ ] 是否遵循了单一职责原则？
- [ ] 是否使用了 useCallback/useMemo？(需要时)
- [ ] 是否有过度优化？
- [ ] 代码是否易于测试？

### 文档

- [ ] 是否有清晰的注释？
- [ ] 是否更新了 README？
- [ ] JSDoc 是否完整？
- [ ] 是否有示例代码？

### 代码风格

- [ ] 是否一致地使用了命名风格？
- [ ] 是否可以进一步简化？
- [ ] 是否可以使用更好的库？

---

## 检查技巧

### 快速检查

```bash
# 1. 检查代码格式和 lint
npm run lint
npm run format

# 2. 运行测试
npm test

# 3. 检查类型
npm run type-check

# 4. 本地验证功能
npm dev
```

### 重点审查项

按照以下顺序重点审查：

1. **功能实现** - 是否实现了需求
2. **安全性** - 有无安全漏洞
3. **测试** - 是否有适当的测试
4. **类型** - TypeScript 类型是否完整
5. **规范** - 是否遵循代码规范
6. **性能** - 是否有性能问题
7. **可读性** - 代码是否易于理解

# 第三步：检查逻辑

代码逻辑是否正确，是否有 bug。

---

## 🎯 这一步的目的

- 发现逻辑错误
- 识别潜在的 bug
- 验证算法的正确性
- 确保功能符合需求

---

## 📝 需要检查的内容

### 1. 业务逻辑

- [ ] 逻辑是否实现了需求？
- [ ] 处理了所有的边界情况吗？（null、empty、undefined）
- [ ] 有没有逻辑漏洞？（可能导致错误结果）
- [ ] 条件判断是否准确？（if/else 逻辑是否正确）
- [ ] 循环是否正确？（是否会无限循环、或遗漏元素）

### 2. 错误处理

- [ ] 是否处理了 API 失败？
- [ ] 是否处理了网络超时？
- [ ] 是否处理了用户输入错误？
- [ ] 错误提示是否清晰？
- [ ] 是否有 try-catch？

### 3. 数据流

- [ ] 数据从哪里来？（props、state、API、localStorage）
- [ ] 数据流向是否正确？
- [ ] 有没有数据泄露？（不应该暴露的数据）
- [ ] 状态更新是否正确？（是否有副作用）
- [ ] 是否修改了 props？（应该避免）

### 4. 异步操作

- [ ] 异步操作是否正确处理？
- [ ] Promise 链或 async/await 是否正确？
- [ ] 有没有竞态条件？（多个异步同时进行时的问题）
- [ ] 清理工作（cleanup）是否完整？
- [ ] 取消机制是否正确？

### 5. 性能问题

- [ ] 有没有无限循环？
- [ ] 有没有频繁的重新渲染？（React 组件）
- [ ] 有没有内存泄漏？
- [ ] 算法复杂度可以接受吗？
- [ ] 是否可以优化？

### 6. 常见的 bug 模式

检查以下常见问题：

- [ ] **闭包陷阱** - 循环中的闭包是否正确？
- [ ] **异步问题** - await 的位置是否正确？
- [ ] **引用问题** - 是否混淆了对象引用和值复制？
- [ ] **副作用** - 是否有无意的全局变量修改？
- [ ] **类型问题** - 是否有类型不匹配？
- [ ] **空值问题** - 是否正确处理了 null/undefined？

---

## 🚩 发现 bug？

如果发现逻辑问题或 bug：

1. **位置** - 说明在哪个文件、哪些行
2. **问题描述** - 详细说明问题是什么
3. **影响** - 这个 bug 会导致什么后果
4. **建议** - 如何修复
5. **代码示例** - 如果可能，给出修复示例

**示例：**
```
【问题】没有处理 API 失败
文件：UserProfile.tsx, 第 45-50 行

问题描述：当 fetchUser 失败时，代码直接使用 user 对象，
会导致 undefined 错误

影响：用户在网络错误时会看到白屏或错误

修复建议：添加 try-catch 或错误状态处理
```

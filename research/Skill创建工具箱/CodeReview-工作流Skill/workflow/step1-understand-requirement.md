# 第一步：理解需求

在开始审查代码前，先理解**这个 PR/MR 要做什么**。

---

## 🎯 这一步的目的

- 了解需求背景
- 知道改动的范围
- 识别潜在的风险点
- 为后续审查做准备

---

## 📝 需要检查的内容

### 1. PR/MR 的基本信息

- [ ] 有 PR/MR 标题吗？
- [ ] 标题清晰说明了改动是什么？
- [ ] 有 PR/MR 描述吗？
- [ ] 描述说明了**为什么**要做这个改动？
- [ ] 有关联的需求地址吗？（可选，支持跳过）

**如果有需求地址：**
- [ ] 粘贴需求地址：`[需求地址]`
- [ ] 我阅读了需求的关键内容

### 2. 改动范围

- [ ] 改动了哪些文件？
- [ ] 改动了多少行代码？（建议 <500 行）
- [ ] 是新增功能、修复 bug 还是重构？
- [ ] 涉及几个模块？

### 3. 关键问题

在开始详细审查前，问自己以下问题：

**1. 这个改动的目的是什么？**
```
[简述改动的核心目标]
```

**2. 会影响哪些功能模块？**
```
[列出受影响的模块]
```

**3. 有什么潜在的风险？**
```
[列出可能的风险]
```

**4. 需要特别关注什么？**
```
[列出需要重点检查的地方]
```

---

## ✅ 完成标志

当你能回答上面的 4 个关键问题时，说明你已经充分理解了需求。

---

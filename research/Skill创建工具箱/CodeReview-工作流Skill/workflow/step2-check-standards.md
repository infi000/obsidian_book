# 第二步：检查规范

代码是否遵守了你的规范和约定。

---

## 🎯 这一步的目的

- 确保代码符合团队规范
- 发现代码风格问题
- 验证命名是否正确
- 发现不规范的写法

---

## 📝 需要检查的内容

### 1. 代码风格

参考知识库中的**代码规范**：

- [ ] 变量声明用了 const/let 吗？（禁止 var）
- [ ] 使用了 arrow function 吗？
- [ ] 函数复杂度合理吗？（建议不超过 15 行）
- [ ] 有必要的注释吗？（复杂逻辑需要注释）
- [ ] 代码格式一致吗？（缩进、空格等）
- [ ] 没有留下 console.log 或 debugger 吗？

### 2. 命名规范

参考知识库中的**命名规范**：

- [ ] 文件名符合规范吗？（PascalCase for components）
- [ ] 变量名清晰有意义吗？（camelCase）
- [ ] 函数名描述了功能吗？
- [ ] 常量用 UPPER_SNAKE_CASE 吗？
- [ ] 缩写词用法正确吗？（不要用单个字母）

### 3. TypeScript 类型

- [ ] 有 TypeScript 类型定义吗？
- [ ] 有使用 any 类型吗？（应该避免）
- [ ] 接口名用了正确的前缀吗？（如 I）
- [ ] 类型定义完整吗？（没有遗漏字段）

### 4. 导入和依赖

- [ ] 导入是否按规范排序？（内置 > 第三方 > 本地）
- [ ] 有未使用的导入吗？
- [ ] 有循环依赖吗？
- [ ] 依赖版本合理吗？

---

## 🚩 发现问题？

如果发现规范问题：

1. **标注位置** - 说明在哪个文件、哪一行
2. **说明问题** - 说明违反了什么规范
3. **给出建议** - 如何改进
4. **引用规范** - 链接到知识库中的相关规范

**示例：**
```
【问题】变量名不清晰
文件：UserProfile.tsx, 第 25 行
当前：const d = userData
问题：变量 d 不清晰，不易理解
建议：改为 const userProfileData = userData
参考：知识库 > 命名规范
```
